## 1. 스택 매개변수와 지역 변수가 있는 프로시저의 에필로그에는 어떤 명령이 포함되는가?

**번역:** 프로시저에 스택 매개변수와 지역 변수가 있을 때, 에필로그에는 어떤 명령문이 들어가는가?

**풀이:** 프레임 포인터를 사용하는 전형적인 에필로그는 다음과 같습니다.

```asm
mov  esp, ebp        ; 지역 변수 공간과 임시 스택 사용분을 버림
pop  ebp             ; 호출자의 프레임 포인터 복원
ret                  ; 복귀
```

매개변수 정리 방법은 호출 규약에 따라 다릅니다. `STDCALL`처럼 피호출자가 매개변수를 정리한다면 `ret n`을 사용해 반환 주소와 함께 `n`바이트의 매개변수도 제거합니다. `C` 호출 규약에서는 보통 호출자가 호출 뒤에 매개변수 공간을 정리합니다.

## 2. C 함수가 32비트 정수를 반환하면 반환값은 어디에 저장되는가?

**풀이:** `EAX` 레지스터에 저장됩니다.

## 3. STDCALL 호출 규약을 사용하는 프로그램은 프로시저 호출 뒤 스택을 어떻게 정리하는가?

**풀이:** 피호출 프로시저가 반환할 때 `ret n`을 실행하여 스택 매개변수 `n`바이트를 정리합니다. 따라서 호출자는 같은 매개변수 공간을 다시 제거하지 않습니다.

## 4. LEA 명령은 OFFSET 연산자보다 어떤 점에서 더 강력한가?

**풀이:** `OFFSET`은 레이블이나 데이터 항목의 주소 오프셋을 얻는 데 사용됩니다. `LEA`는 유효 주소 계산식의 결과를 레지스터에 넣으므로, 기본 주소·인덱스·배율·변위를 조합해 주소를 계산할 수 있습니다. 또한 계산된 주소를 적재할 뿐, 해당 메모리의 값을 읽지는 않습니다.

```asm
lea eax, [ebx + esi*4 + 8] ; 주소 계산 결과를 EAX에 저장
```

## 5. 8.2.3절의 C++ 예제에서 `int` 변수는 스택 공간을 얼마나 사용하는가?

**풀이:** 예제의 32비트 환경에서 `int` 하나는 보통 **4바이트**를 차지합니다.

## 6. C 호출 규약은 STDCALL보다 어떤 장점이 있을 수 있는가?

**풀이:** 호출자가 인수를 정리하므로, 가변 개수의 인수를 받는 함수(예: `printf`)를 구현하기 쉽습니다. 호출 지점마다 실제 전달한 인수 개수가 다르더라도 피호출 함수가 고정된 정리 바이트 수를 가정할 필요가 없습니다.

## 7. 참/거짓: PROC 지시어를 사용할 때 모든 매개변수는 같은 줄에 나열해야 한다.

**정답: 거짓.**

MASM에서는 줄 끝에 쉼표를 두어 매개변수 목록을 다음 줄로 이어 쓸 수 있습니다.

```asm
Example PROC, arg1:DWORD, arg2:DWORD, \
             arg3:DWORD
```

## 8. 참/거짓: 바이트 배열의 오프셋이 들어 있는 변수를 워드 배열 포인터를 기대하는 프로시저에 전달하면, 어셈블러가 오류로 표시한다.

**정답: 거짓.**

일반적으로 전달되는 값은 주소이므로, 어셈블러가 그 주소가 실제로 바이트 배열인지 워드 배열인지까지 확인하지 못할 수 있습니다. 따라서 호출이 어셈블되더라도 프로시저가 워드 단위로 접근하면 의도와 다른 메모리를 읽거나 쓸 수 있습니다. 포인터의 원소 형식이 다르다는 점을 프로그래머가 확인해야 합니다.

## 9. 참/거짓: 참조 매개변수를 기대하는 프로시저에 즉시값을 전달하면 일반 보호 예외(GPF)가 발생할 수 있다.

**정답: 참.**

참조 매개변수는 실제로는 대상 객체의 주소를 전달합니다. 즉시값을 주소처럼 전달한 뒤 프로시저가 그 주소를 역참조하면, 유효하지 않거나 접근할 수 없는 메모리를 참조하여 보호 예외가 발생할 수 있습니다.
