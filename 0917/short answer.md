### 1. 서로 다른 명령어 니모닉 3개의 예를 제시하라.

- `MOV`: 데이터를 복사한다.
- `ADD`: 두 값을 더한다.
- `JMP`: 지정한 위치로 무조건 분기한다.

### 2. 호출 규약(calling convention)이란 무엇이며, 어셈블리 언어 선언에서 어떻게 사용되는가?

호출 규약은 **인자를 전달하는 순서와 방법**, **반환값의 위치**, **호출 후 스택을 정리하는 주체**, **보존해야 하는 레지스터** 등을 정하는 규칙이다.

MASM에서는 프로시저 선언(`PROTO`, `PROC`)에 `STDCALL`, `C`, `FASTCALL` 등의 호출 규약을 지정할 수 있다. 이를 통해 호출 코드와 프로시저가 동일한 인자 전달 규칙을 사용하도록 만든다.

```asm
Example PROC STDCALL, value:DWORD
    ; ...
    ret
Example ENDP
```

### 3. 프로그램에서 스택 공간은 어떻게 예약하는가?

`.stack` 지시문 뒤에 필요한 바이트 수를 지정한다.

```asm
.stack 4096
```

위 예시는 스택으로 4096바이트를 예약한다.

### 4. `assembler language`라는 표현이 완전히 정확하지 않은 이유를 설명하라.

어셈블리 언어는 하나의 보편적 언어가 아니라 **특정 프로세서 아키텍처와 어셈블러에 종속된 언어군**이다. 예를 들어 x86용 어셈블리와 ARM용 어셈블리는 명령어와 문법이 다르며, 같은 x86이라도 MASM과 NASM의 문법에는 차이가 있을 수 있다. 따라서 단수형 표현보다 `assembly language`가 일반적으로 쓰인다.

### 5. 빅 엔디언과 리틀 엔디언의 차이를 설명하고, 용어의 유래를 조사하라.

여러 바이트로 이루어진 값을 메모리에 저장할 때 바이트의 순서를 정하는 방식이다.

| 구분 | 저장 방식 | 32비트 값 `12345678h`를 낮은 주소부터 저장한 예 |
|---|---|---|
| 빅 엔디언(Big Endian) | 최상위 바이트(MSB)를 먼저 저장 | `12 34 56 78` |
| 리틀 엔디언(Little Endian) | 최하위 바이트(LSB)를 먼저 저장 | `78 56 34 12` |

x86 계열 프로세서는 일반적으로 **리틀 엔디언** 방식을 사용한다.

이 용어는 조너선 스위프트의 소설 *걸리버 여행기*에서 달걀의 어느 쪽 끝을 먼저 깨야 하는지를 두고 대립한 **Big-Endians**와 **Little-Endians**에서 유래했다.

### 6. 코드에서 정수 리터럴 대신 기호 상수를 사용하는 이유는 무엇인가?

기호 상수는 코드의 의미를 분명하게 하고, 값이 바뀌어도 한 곳만 수정하면 되므로 유지보수가 쉽다.

```asm
MAX_COUNT = 100
mov ecx, MAX_COUNT
```

`100`만 직접 쓰는 것보다 `MAX_COUNT`가 무엇을 뜻하는지 훨씬 명확하다.

### 7. 소스 파일과 리스팅 파일의 차이는 무엇인가?

| 구분 | 설명 |
|---|---|
| 소스 파일 | 개발자가 작성한 어셈블리 코드 파일이다. 일반적으로 `.asm` 확장자를 사용한다. |
| 리스팅 파일 | 어셈블러가 생성하는 출력 파일이다. 소스 코드와 주소, 기계어 코드, 오류 정보 등을 함께 보여 주어 디버깅과 분석에 사용한다. 일반적으로 `.lst` 확장자를 사용한다. |

### 8. 데이터 레이블과 코드 레이블은 어떻게 다른가?

- **데이터 레이블**은 메모리에 선언된 데이터의 위치를 이름으로 나타낸다.
- **코드 레이블**은 실행할 명령어의 위치를 이름으로 나타내며, 분기 또는 호출 대상이 될 수 있다.

```asm
count DWORD 10      ; 데이터 레이블

start:               ; 코드 레이블
    mov eax, count
```

### 9. (참/거짓) 식별자는 숫자로 시작할 수 없다.

**참(True)**. 식별자는 일반적으로 영문자, 밑줄(`_`), `@`, `$`, `?` 등으로 시작해야 하며 숫자로 시작할 수 없다.

### 10. (참/거짓) 16진수 리터럴은 `0x3A`처럼 쓸 수 있다.

**거짓(False)**. MASM에서는 보통 접미사 `h`를 사용하여 `3Ah`처럼 작성한다. 숫자로 시작하지 않는 경우에는 앞에 `0`을 붙여야 한다.

```asm
3Ah
0ABCh
```

### 11. (참/거짓) 어셈블리 언어 지시문은 실행 시간에 실행된다.

**거짓(False)**. 지시문(directive)은 어셈블 단계에서 어셈블러에게 데이터 배치, 세그먼트 구성 등의 정보를 제공한다. CPU가 실행 시간에 실행하는 명령어가 아니다.

### 12. (참/거짓) 어셈블리 언어 지시문은 대문자와 소문자를 어떤 조합으로든 작성할 수 있다.

**참(True)**. MASM은 기본적으로 대소문자를 구별하지 않는다. 예를 들어 `DWORD`, `Dword`, `dword`는 같은 지시문으로 처리된다.

### 13. 어셈블리 언어 명령문의 네 가지 기본 부분을 쓰라.

1. 레이블(label)
2. 명령어 니모닉(instruction mnemonic)
3. 피연산자(operand)
4. 주석(comment)

모든 명령문이 네 부분을 모두 반드시 포함하는 것은 아니다.

### 14. (참/거짓) `MOV`는 명령어 니모닉의 예이다.

**참(True)**. `MOV`는 데이터를 복사하는 명령어를 나타내는 니모닉이다.

### 15. (참/거짓) 코드 레이블 뒤에는 콜론(`:`)이 붙지만, 데이터 레이블 끝에는 콜론이 붙지 않는다.

**참(True)**. 일반적인 MASM 데이터 선언에서 데이터 레이블은 자료형 지시문 앞에 쓰며 콜론을 붙이지 않는다.

```asm
target:              ; 코드 레이블
value DWORD 10       ; 데이터 레이블
```

### 16. 블록 주석의 예를 제시하라.

MASM에서는 `COMMENT` 지시문과 구분 문자를 사용한다.

```asm
COMMENT !
이 영역은 블록 주석입니다.
여러 줄에 걸쳐 작성할 수 있습니다.
!
```

### 17. 변수를 접근하는 명령어를 작성할 때 숫자 주소를 사용하는 것이 좋지 않은 이유는 무엇인가?

숫자 주소를 직접 사용하면 코드의 의미를 파악하기 어렵고, 데이터 위치가 변경될 때 관련 주소를 모두 수정해야 한다. 또한 재배치(relocation)와 유지보수에 불리하다. 변수 이름이나 데이터 레이블을 사용하면 어셈블러와 링커가 올바른 주소를 처리한다.

### 18. `ExitProcess` 프로시저에는 어떤 종류의 인자를 전달해야 하는가?

프로세스의 종료 상태를 나타내는 **32비트 종료 코드(`DWORD`)**를 전달해야 한다.

```asm
INVOKE ExitProcess, 0
```

일반적으로 `0`은 정상 종료를 뜻한다.

### 19. 프로시저를 끝내는 지시문은 무엇인가?

`ENDP` 지시문이다.

```asm
MyProc PROC
    ret
MyProc ENDP
```

### 20. 32비트 모드에서 `END` 지시문의 식별자는 어떤 용도인가?

`END` 뒤의 식별자는 프로그램의 **진입점(entry point)**, 즉 실행을 시작할 코드 레이블을 지정한다.

```asm
END main
```

### 21. `PROTO` 지시문의 목적은 무엇인가?

`PROTO`는 프로시저의 이름, 호출 규약, 매개변수의 개수와 자료형을 미리 선언하는 **프로시저 원형(prototype)** 지시문이다. `INVOKE` 사용 시 올바른 인자 전달과 형식 검사를 돕는다.

```asm
ExitProcess PROTO, dwExitCode:DWORD
```

### 22. (참/거짓) 오브젝트 파일은 링커가 만든다.

**거짓(False)**. 오브젝트 파일(`.obj`)은 **어셈블러**가 만든다. 링커는 오브젝트 파일과 라이브러리를 결합하여 실행 파일을 만든다.

### 23. (참/거짓) 리스팅 파일은 어셈블러가 만든다.

**참(True)**. 리스팅 파일은 어셈블 과정에서 어셈블러가 생성할 수 있다.

### 24. (참/거짓) 링크 라이브러리는 실행 파일을 만들기 직전에 프로그램에 추가된다.

**참(True)**. 링커는 오브젝트 파일과 필요한 링크 라이브러리를 결합한 뒤 실행 파일을 생성한다.

### 25. 32비트 부호 있는 정수 변수를 생성하는 데이터 지시문은 무엇인가?

`SDWORD`

```asm
signedValue SDWORD -100
```

### 26. 16비트 부호 있는 정수 변수를 생성하는 데이터 지시문은 무엇인가?

`SWORD`

```asm
signedWord SWORD -10
```

### 27. 64비트 부호 없는 정수 변수를 생성하는 데이터 지시문은 무엇인가?

`QWORD`

```asm
largeValue QWORD 123456789
```

### 28. 8비트 부호 있는 정수 변수를 생성하는 데이터 지시문은 무엇인가?

`SBYTE`

```asm
signedByte SBYTE -5
```

### 29. 10바이트 패킹 BCD 변수를 생성하는 데이터 지시문은 무엇인가?

`TBYTE`

```asm
packedValue TBYTE ?
```

`TBYTE`는 10바이트 저장 공간을 예약하며, x87 80비트 확장 정밀도 부동소수점 값 또는 10바이트 패킹 BCD 값과 관련된 데이터 선언에 사용될 수 있다.
