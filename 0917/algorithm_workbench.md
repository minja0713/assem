## 1. 10진수, 2진수, 8진수, 16진수 형식으로 정수 `25`를 나타내는 기호 상수 네 개를 정의하라.

MASM에서는 진법을 나타내는 접미사를 사용할 수 있다.

```asm
DEC_25 = 25       ; 10진수
BIN_25 = 11001b   ; 2진수
OCT_25 = 31o      ; 8진수
HEX_25 = 19h      ; 16진수
```

모든 상수는 같은 값인 $25_{10}$을 의미한다.

| 진법 | 표현 | 값 |
|---|---:|---:|
| 10진수 | `25` | $25$ |
| 2진수 | `11001b` | $16+8+1=25$ |
| 8진수 | `31o` | $3 \times 8 + 1 = 25$ |
| 16진수 | `19h` | $1 \times 16 + 9 = 25$ |

## 2. 하나의 프로그램이 여러 코드 세그먼트와 데이터 세그먼트를 가질 수 있는지 실험으로 확인하라.

**가능하다.** 다만 간소화된 세그먼트 지시문인 `.data`, `.code`만 사용하는 기본 예제보다, 명시적 세그먼트 선언(`SEGMENT` / `ENDS`)을 사용하면 여러 세그먼트를 분명하게 정의할 수 있다.

```asm
.data
data1 DWORD 1111h

.data?
data2 DWORD ?

.code
main PROC
    ; 첫 번째 코드 영역
    ret
main ENDP

ExtraCode SEGMENT
extraProc PROC
    ret
extraProc ENDP
ExtraCode ENDS

END main
```

- `.data`, `.data?`, `.const`는 서로 다른 종류의 데이터 영역을 정의할 때 사용한다.
- 추가 코드 또는 데이터 세그먼트가 필요하면 `SEGMENT`와 `ENDS`를 사용해 명시적으로 선언할 수 있다.
- 실제 프로젝트에서는 링커 설정과 메모리 모델도 함께 고려해야 한다.

## 3. 메모리에 빅 엔디언 형식으로 저장되는 더블워드 데이터 정의를 작성하라.

예를 들어 논리적 값 `12345678h`의 바이트가 낮은 주소부터 `12h`, `34h`, `56h`, `78h` 순으로 저장되게 하려면 x86의 리틀 엔디언 저장 방식을 고려하여 다음처럼 선언할 수 있다.

```asm
bigEndianValue DWORD 78563412h
```

x86은 리틀 엔디언이므로 위 값은 메모리에 다음 순서로 놓인다.

| 메모리 주소 방향 | 저장된 바이트 |
|---|---|
| 낮은 주소 → 높은 주소 | `12h 34h 56h 78h` |

바이트 순서를 직접 명확히 표현하고 싶다면 다음 선언도 가능하다.

```asm
bigEndianBytes BYTE 12h, 34h, 56h, 78h
```

> 주의: `bigEndianBytes`는 4바이트 배열이며, CPU가 이를 하나의 `DWORD`로 읽으면 x86에서는 값 `78563412h`로 해석한다.

## 4. `DWORD` 타입 변수를 선언하고 음수 값을 대입할 수 있는지 확인하라. 이 결과가 어셈블러의 타입 검사에 대해 알려 주는 것은 무엇인가?

가능하다.

```asm
value DWORD -1
```

`DWORD`는 주로 **저장 공간의 크기(32비트)**를 나타낸다. `-1`은 2의 보수 표현인 `FFFFFFFFh`로 저장된다.

이는 어셈블러가 부호 여부를 엄격한 타입 안전성 규칙으로 검사하기보다는, 값이 해당 저장 공간에 들어가는지와 표현 가능한지를 주로 다룬다는 점을 보여 준다. 부호 있는 의미를 코드에 명확히 드러내려면 `SDWORD`를 사용하는 편이 좋다.

```asm
signedValue SDWORD -1
```

## 5. `EAX`에 5를 더하고, `EDX`에 5를 더하는 두 명령어로 프로그램을 작성하라. 리스팅 파일을 생성해 기계어 코드를 비교하라.

### 예제 코드

```asm
INCLUDE Irvine32.inc

.code
main PROC
    add eax, 5
    add edx, 5

    exit
main ENDP
END main
```

작은 즉시값 `5`에 대해 MASM이 일반적으로 생성하는 기계어는 다음과 같다.

| 어셈블리 명령어 | 기계어 코드 | 설명 |
|---|---|---|
| `add eax, 5` | `83 C0 05` | `C0`의 레지스터 필드가 `EAX`를 지정 |
| `add edx, 5` | `83 C2 05` | `C2`의 레지스터 필드가 `EDX`를 지정 |

두 명령어는 모두 3바이트이며, **레지스터를 지정하는 ModR/M 바이트만 다르다.**

> 참고: 생성되는 정확한 바이트는 어셈블러 버전 및 최적화/인코딩 선택에 따라 달라질 수 있다. `5`처럼 부호 있는 8비트 범위($-128$~$127$)에 있는 즉시값은 보통 짧은 형식인 `83 /0 ib` 인코딩이 사용된다.

ML.exe를 사용해 리스팅 파일을 생성하는 한 가지 방법은 다음과 같다.

```bat
ml /c /coff /Fl program.asm
```

이 명령은 보통 `program.lst` 리스팅 파일을 생성한다.

## 6. 수 `456789ABh`의 바이트 값을 리틀 엔디언 순서로 나열하라.

더블워드 `456789ABh`를 바이트 단위로 나누면 다음과 같다.

```text
45h 67h 89h ABh
```

리틀 엔디언에서는 최하위 바이트가 가장 낮은 주소에 저장되므로 메모리 순서는 다음과 같다.

```text
ABh 89h 67h 45h
```

## 7. 초기화되지 않은 부호 없는 더블워드 120개짜리 배열을 선언하라.

```asm
uArray DWORD 120 DUP(?)
```

- `DWORD`: 원소 하나당 4바이트
- `120 DUP(?)`: 초기화되지 않은 원소 120개
- 전체 크기: $120 \times 4 = 480$바이트

초기화하지 않은 데이터 영역에 선언한다면 다음처럼 작성할 수도 있다.

```asm
.data?
uArray DWORD 120 DUP(?)
```

## 8. 바이트 배열을 선언하고 알파벳의 처음 5글자로 초기화하라.

```asm

```

문자열 리터럴을 사용하면 더 간결하다.


## 9. 32비트 부호 있는 정수 변수를 선언하고, 가능한 가장 작은 음의 10진수 값으로 초기화하라.

32비트 부호 있는 정수의 범위는 다음과 같다.

$$-2^{31} \leq n \leq 2^{31}-1$$

따라서 가능한 최소값은 $-2^{31} = -2147483648$이다.

```asm
minValue SDWORD -2147483648
```

## 10. `wArray`라는 이름의 부호 없는 16비트 정수 배열을 세 개의 초기값으로 선언하라.

```asm
wArray WORD 10, 20, 30
```

`WORD`는 16비트 크기의 부호 없는 정수 데이터를 선언할 때 사용할 수 있다.

## 11. 좋아하는 색의 이름을 담는 문자열 변수를 선언하고, 널 종료 문자열로 초기화하라.

예를 들어 좋아하는 색을 `Blue`라고 가정하면 다음과 같이 선언한다.

```asm
favoriteColor BYTE "Blue", 0
```

마지막의 `0`은 C 스타일 문자열의 끝을 나타내는 널 문자(`NULL`)이다. 원하는 색 이름으로 `"Blue"` 부분만 바꾸면 된다.

## 12. `dArray`라는 이름의 초기화되지 않은 부호 있는 더블워드 50개 배열을 선언하라.

```asm
dArray SDWORD 50 DUP(?)
```

초기화되지 않은 데이터 영역을 사용한다면 다음과 같이 선언할 수 있다.

```asm
.data?
dArray SDWORD 50 DUP(?)
```

## 13. `TEST`라는 단어가 500번 반복된 문자열 변수를 선언하라.

```asm
testString BYTE 500 DUP("TEST")
```

문자열의 전체 길이는 다음과 같다.

$$500 \times 4 = 2000\text{ bytes}$$

널 종료 문자열로 만들고 싶다면 마지막에 `0`을 추가한다.

```asm
testString BYTE 500 DUP("TEST"), 0
```

## 14. `bArray`라는 이름의 부호 없는 바이트 20개 배열을 선언하고, 모든 원소를 0으로 초기화하라.

```asm
bArray BYTE 20 DUP(0)
```

전체 크기는 $20 \times 1 = 20$바이트이다.

## 15. 다음 더블워드 변수의 각 바이트가 메모리에서 놓이는 순서를 낮은 주소부터 높은 주소까지 나타내라.

문제의 변수:

```asm
val1 DWORD 87654321h
```

x86은 리틀 엔디언이므로 최하위 바이트부터 저장한다.

| 메모리 주소 방향 | 바이트 값 |
|---|---|
| 가장 낮은 주소 | `21h` |
|  | `43h` |
|  | `65h` |
| 가장 높은 주소 | `87h` |

따라서 메모리 바이트 순서는 다음과 같다.

```text
21h 43h 65h 87h
```

## 핵심 정리

| 항목 | 핵심 문법 또는 내용 |
|---|---|
| 기호 상수 | `NAME = value` |
| 초기화되지 않은 배열 | `TYPE count DUP(?)` |
| 0으로 초기화한 배열 | `TYPE count DUP(0)` |
| 널 종료 문자열 | `BYTE "text", 0` |
| 반복 문자열 | `BYTE count DUP("text")` |
| 32비트 부호 정수 | `SDWORD` |
| 16비트 정수 | `WORD` |
| 리틀 엔디언 | 낮은 주소에 최하위 바이트(LSB)를 저장 |
| 리스팅 파일 생성 예 | `ml /c /coff /Fl program.asm` |
